## 1. 这份计划是什么

**一句话**：在已完成的图书管理系统后端之上，补齐课程评分所需的功能，开发 Vue3 前端，并把它打包部署到服务器上让浏览器远程访问，最后产出课程要求的实验报告。

**四个目标**：

1. **补齐后端缺口**——按《实验大纲》评分点，补上验证码、忘记/重置密码、头像、数据统计等缺失功能。
2. **开发前端**——Vue3 + TypeScript + Element Plus，把现有接口变成可操作的页面。
3. **打包部署**——前端构建产物打进后端 jar，服务器启动后浏览器直接访问。
4. **产实验报告**——覆盖《实验大纲》要求的文档内容。

**与现有计划的关系**：现有 12 周计划的后端目标已基本达成，本计划不再重复后端主流程，只规划"新增功能 + 前端 + 部署 + 报告"。两者可并行参照，本计划更细、更偏落地。

**协作方式**（沿用项目一贯约定）：**讲概念 → 成员自己写代码 → 互相 review → 改**。计划只规定"做什么、谁做、做到什么程度"，不代写代码。

## 3. 现状盘点

### 3.1 后端已完成（可直接复用）

| 模块 | 接口 | 权限 |
| --- | --- | --- |
| 用户 | `POST /api/user/register` 注册、`POST /api/user/login` 登录、`PUT /api/user/logout` 退出 | 公开 |
| 用户 | `GET /api/user/list` 用户列表、`GET /api/user/{id}` 按 id 查、`PUT /api/user/{id}/status` 禁用/启用、`DELETE /api/user/{id}` 删除 | 管理员 |
| 用户 | `PUT /api/user/name` 改用户名、`PUT /api/user/password` 改密码 | 登录即可 |
| 图书 | `GET /api/book/list`、`GET /api/book/{id}`、`POST/PUT/DELETE /api/book`（增删改） | 查询公开，增删改管理员 |
| 副本 | `GET /api/book-copy/list`、`GET /api/book-copy/{id}`、`POST/PUT/DELETE /api/book-copy` | 查询公开，增删改管理员 |
| 借阅 | `POST /api/borrow` 借书、`PUT /api/borrow/return` 还书、`GET /api/borrow/my` 我的记录、`GET /api/borrow/{id}` 某用户记录 | 借还登录，查他人管理员 |

### 3.2 前端 = 空白

目前没有任何前端工程，全部待建。

### 3.3 关键契约（前端对接必须遵守，已从代码确认）

| 项 | 约定 |
| --- | --- |
| 统一返回结构 | `{ code, message, data }` |
| 成功 | `code = 200`，`message = "ok"` |
| 错误 | `code` 与 HTTP 状态一致：400 参数/业务、401 未登录、403 无权限/禁用、404 不存在、500 服务错误 |
| 登录返回 | `{ token, id, username, role }`，`role`：0=普通用户、1=管理员 |
| 鉴权方式 | 请求头携带 token，**header 名是 `satoken`**（Sa-Token 默认，非自定义 `token`） |
| 角色 | 管理员 `admin`，普通用户 `user` |

> ⚠️ 课程指南示例里的 `{code, msg}` 和 `/api/auth/login` 是它自带模板的写法，**我们不照搬**；我们用自己的后端，前端严格对齐上表。

## 5. 技术方案

### 5.1 前端工程

- **创建方式**：`npm create vite@latest`，选 Vue + TypeScript；工程目录放在仓库根的 `frontend/`（与 `src/`、`pom.xml` 平级）。
- **核心依赖**：`element-plus`、`vue-router`、`pinia` + `pinia-plugin-persistedstate`、`axios`、`vue-echarts`（ECharts）、`sass`、`js-base64`。
- **目录结构（示意）**：

```
frontend/
  src/
    main.ts              # 入口：挂载 Element Plus / Pinia / Router
    App.vue              # 根组件
    router/index.ts      # 路由表（页面跳转必须在此注册）
    stores/              # Pinia：登录态、用户信息（持久化）
    models/              # TS 数据类型接口（对应后端 DTO/实体）
    services/            # axios 封装 + 各模块请求函数
    styles/              # 全局 SCSS
    components/Navi.vue  # 主框架（logo + 二级菜单 + 头像 + 版权）
    views/               # 各页面 .vue
```

- **页面清单（对应评分点）**：
  - `Login.vue`（登录 + 图形验证码 + 忘记密码入口）、`Register.vue`（注册）、`ForgotPassword.vue`（忘记/重置密码）
  - `Navi.vue`（主框架：logo、二级菜单、头像、版权）
  - `MainPage.vue`（ECharts 数据统计首页）
  - `Profile.vue`（个人信息维护 + 改密码 + 头像上传）
  - `UserManage.vue`（管理员：用户列表/禁用/删除）
  - `BookManage.vue`、`BookCopyManage.vue`（图书/副本增删改查）
  - `BorrowManage.vue`（借书/还书/借阅记录）
  - `AnnounceManage.vue`（公告，加分项）
  - `ProjectIntro.vue`（项目展示）、`TeamIntro.vue`（团队介绍，含动画/多媒体）

### 5.2 通信约定（前端）

- **axios 封装**：统一 baseURL 与 `/api` 前缀，请求拦截器从 Pinia/localStorage 读 token 塞进 header `satoken`，响应拦截器统一处理 `code !== 200` 的错误提示与 401 跳登录。
- **token 持久化**：登录成功后把 `{token, id, username, role}` 存进 Pinia + localStorage，页面刷新后恢复（满足"刷新不丢会话"）。
- **开发期联调**：`vite.config.ts` 配 `server.proxy`，把 `/api` 代理到 `http://localhost:8080`（本后端端口），避免跨域。

### 5.3 打包部署方案（前端打进 jar）

1. 前端 `vite.config.ts` 设置 `build.outDir` 指向后端静态目录 `../src/main/resources/static`。
2. `npm run build` → 产物（`index.html` + `assets/*`）落到后端 `resources/static`。
3. `mvn clean package` → Spring Boot 把 `static` 一起打进 jar。
4. 服务器上 `java -jar xxx.jar` → 浏览器访问 `http://服务器IP:8080/` 直接看到前端，前端再调用同源 `/api/*`。

> 开发期用 vite proxy 联调；只有**打包上线**时才执行"build → 打进 jar"两步。

## 6. 分阶段计划

> 时间按"双人并行、每人每天约 1.5 小时"估算，可随课业调整。每阶段都遵守"讲概念→写→review→改"。

### 阶段一：前端骨架 + 最小闭环（共同）

**目标**：把前端工程搭起来，用一个接口跑通"前端 → 后端 → 返回"全链路。

- 环境：Node.js + VSCode 插件（ESLint / Volar / Vue Official / Vite）。
- 创建 Vite+Vue+TS 工程，安装依赖，配置 `@` 别名、vite proxy。
- 写 axios 封装 + 登录请求函数，接现有 `POST /api/user/login`，实现"输入账号密码 → 拿 token → 存 Pinia"。
- 最小 `Login.vue` + 路由，登录成功后跳到一个占位页。

**产出**：前端工程可运行，登录接口调通，token 能持久化。
**分工**：两人一起搭骨架（这是后续各自开发的地基，必须都懂）。

### 阶段二：登录注册与账号安全（A 同学主导）

**目标**：把"用户/权限/安全"这条线做成完整闭环，覆盖 10 分评分点。

- **后端**：图形验证码接口（生成 + 存 Redis + 校验）；`user` 表加 `email`、`avatar` 字段；忘记密码 + 重置密码接口；更新个人信息接口；头像上传接口。
- **前端**：`Login.vue`（含验证码）、`Register.vue`、`ForgotPassword.vue`、`Profile.vue`（改资料/改密码/传头像）。
- **B 同学**：review + 联调本阶段页面，同时准备阶段三的接口对齐。

**产出**：注册 → 登录 → 忘记密码 → 重置 → 改个人信息 → 传头像，全流程可点。
**关键点**：新增的验证码/忘记密码/重置密码接口都是**未登录可访问**，必须同步放行（见风险 R1）。

### 阶段三：核心业务页面（B 同学主导）

**产出**：图书 → 副本 → 借书 → 还书 → 借阅记录，完整业务链路可点。

## 9. 打包部署完整流程（通用）

> 不绑定具体服务器，下面步骤在任何装了 JDK 21 的服务器（云服务器/局域网机器/本机）都适用。

1. **准备服务器环境**：JDK 21、MySQL 8、Redis（与后端 pom 已引入的依赖对应）。
2. **配置数据库**：在服务器 MySQL 执行 `db/init.sql`，建库建表。
3. **配置环境变量**（后端已从环境变量读敏感信息，不写死）：
   - `MDB_PASSWORD`：MySQL 密码
   - `RDB_PASSWORD`：Redis 密码
   - `ADMIN_INIT_PASSWORD`：初始管理员密码
4. **前端打包**：在 `frontend/` 执行 `npm install && npm run build`，产物落到后端 `resources/static`。
5. **后端打包**：`mvn clean package`，得到 `target/book-management-0.0.1-SNAPSHOT.jar`。
6. **部署运行**：`java -jar book-management-0.0.1-SNAPSHOT.jar`（可加 `--spring.profiles.active=prod` 区分生产配置）。
7. **远程访问**：浏览器打开 `http://服务器IP:8080/`，进入登录页。

**可选进阶**（时间够再做，非必需）：Docker 打包、Nginx 反代 + 域名、HTTPS。

## 11. 风险与注意点

| 编号 | 风险/注意 | 应对 |
| --- | --- | --- |
| R1 | **打包后前端静态资源被 401 拦截**：当前 `SaTokenConfig` 拦截 `/**`，仅放行 `login/register`，前端 `index.html`、`assets/*` 也会被要求登录 → 页面打不开 | 在 `excludePathPatterns` 放行 `/`、`/index.html`、`/assets/**`、`/favicon.ico` 等静态路径；新增的验证码/忘记密码/重置密码接口也要一并放行。**这是打包前必须先解决的头号问题** |
| R2 | **token header 名不一致** | 前端统一用 `satoken`（Sa-Token 默认），或后端配置 `token-name: token` 后前端对齐，二选一，别各写各的 |
| R3 | **团队 2 人 vs 课程要求 3-5 人** | 提前跟老师确认 2 人可否；不行则说明分工充分（每人贯穿前后端）或补人 |
| R4 | **MyBatis-Plus vs 课程 JPA** | 指南"不限制技术路线"，MyBatis-Plus 是国内主流，非"非主流"，成绩影响可控；保持不动，避免重写 |
| R5 | **忘记密码的验证码怎么发** | 无邮件服务时：① 用**图形验证码**替代"邮件验证码"作为重置凭证（最简单，仍满足"检查验证码"）；② 或接一个免费邮箱 SMTP。**推荐 ①**，先跑通再说 |
| R6 | **前端打进 jar 的代价** | 每次改前端都要重新 build + 打包，开发期用 vite proxy 规避；上线前才走完整打包 |
| R7 | **端口与路径** | 后端端口 8080，前端所有请求前缀 `/api`，vite 代理目标与生产 baseURL 要一致 |
| R8 | **公告/统计等新表新接口** | 表结构变更两人同步；新接口先补进接口文档再开发（沿用协作规则） |
